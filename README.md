# CamoChat (陈仓)

English | [中文](README.cn.md)

CamoChat (Chencang, 陈仓) is an end-to-end encrypted messaging app for iOS and Android that **has no channel of its own**.
It looks like an ordinary chat app (threads, contacts, seal / unseal), but a message is encrypted on the device into a
short piece of text and carried by any messenger you already use (WeChat, QQ, ...) via copy-paste or the system share sheet.
The recipient decrypts it in CamoChat. There is no keyboard or input-method extension.

## How it works

- **Text is zero-server and zero-network.** Identity, prekeys, pairing, encryption and decryption all run on the device.
  The text path makes no network requests and there are no accounts.
- **Receiving.** Ciphertext comes back into the app through the iOS Action Extension, the Android `ACTION_PROCESS_TEXT`
  menu, a share, or paste.
- **Voice / images / video** are encrypted on the device into a blob and uploaded to an object-storage relay; the chat
  carries only a short encrypted locator. The relay sees ciphertext only. Its source is in [`infra/media/`](infra/media/).
- **Signed config.** The apps fetch a public, Ed25519-signed config file (`chencang-config.json`, source in
  [`release/config/`](release/config/)). It carries no personal or device information.
- **Pairing** is in-band: two parties exchange a short signed message carrying the prekey bundle (as a link, QR card or text),
  both derive a matching session, and confirm it by comparing an emoji fingerprint. No server mediates.

The only sanctioned network uses are the media relay, the signed config fetch, and the update download of the Android
"direct" flavor (the Play flavor and iOS only fetch the config).

## Security summary

Full description: [`docs/protocol/README.md`](docs/protocol/README.md) (written in Chinese; the code is authoritative).

- **Classical suite (0x01), the default:** X25519 + Ed25519, in-band X3DH handshake with key confirmation.
- **Post-quantum suite (0x02):** ML-KEM-768 + ML-DSA-65 hybrid. It is compiled into the core library but not enabled in the clients
  (its public keys are too large to fit a pairing message into a QR code or a paste).
- **Ratchet:** the DH ratchet steps only once, after which messages continue on symmetric chains. See section 6 of the protocol
  notes for the exact semantics rather than assuming a textbook Double Ratchet.
- **Authentication:** both sides compare an emoji fingerprint after pairing.
- AEAD is XChaCha20-Poly1305; the core is pure Rust with KAT suites for every primitive.

## Repository layout

| Path | What |
|---|---|
| `core/` | `chencang-core`: pure Rust crypto / protocol library (no I/O, no async, no platform code) |
| `bindings/` | UniFFI layer producing a Swift XCFramework and an Android AAR; `bindings/xtask/` drives all builds |
| `ios/` | iOS app and Action Extension (Xcode project generated by XcodeGen from `ios/project.yml`) |
| `android/` | Android app (Gradle modules `:app`, `:shared`, `:design`) |
| `design/` | Design tokens (Style Dictionary) generating colour / size / font constants for both platforms |
| `infra/media/` | Rich-media ciphertext relay (object storage + upload-signer Lambda + CDN routes) |
| `release/config/` | Signed public config (`payload.json` source, `chencang-config.json` signed artifact) |
| `site/` | Static website (GitHub Pages) |
| `docs/protocol/` | Protocol notes |
| `scripts/` | `public-scan.sh`, the repository hygiene gate |

Build chain: `core` (Rust) -> `bindings` (UniFFI) -> clients (Swift / Kotlin). Clients never touch `core` directly;
they consume the generated XCFramework / AAR.

## Build & test

### Rust (core + bindings)

CI uses the `stable` toolchain (the dependency tree pulls `edition = "2024"` crates). `.cargo/config.toml` sets
`RUST_MIN_STACK = 16777216` globally; this is mandatory because ML-KEM-768 stack buffers overflow the default test-thread
stack in debug builds. Do not remove it.

```sh
cargo test --workspace
cargo test -p chencang-core                          # core only (unit + integration + KATs)
cargo test -p chencang-core <name>                   # single test by name
cargo test -p chencang-core --test kat_ml_kem_768    # single integration test file
cargo clippy --all-targets --all-features -- -D warnings   # CI gate
cargo fmt --all                                      # CI gate
```

`core/tests/` holds KAT suites (X25519, Ed25519, XChaCha20-Poly1305, BLAKE2b, ML-KEM-768, ML-DSA-65) plus e2e / wire / blob
round-trips. Golden-vector generators are `#[ignore]` because they write files; regenerate the cross-language fixture with
`cargo run -p xtask -- golden-vectors` (seeded and byte-identical; CI checks that `bindings/golden-vectors/vectors.json` is unchanged).

### Bindings and client artifacts (xtask)

```sh
cargo run -p xtask -- gen-bindings   # regenerate Swift + Kotlin FFI (committed; CI fails on drift)
cargo run -p xtask -- build-ios      # -> bindings/swift/ChencangCore.xcframework (gitignored)
ANDROID_NDK_HOME=/path/to/ndk cargo run -p xtask -- build-android   # needs Android NDK 27 + cargo-ndk
```

Generated Swift (`bindings/swift/Sources/Chencang/`) and Kotlin (`bindings/android/.../src/main/java/`) are committed.
After any change to `chencang.udl` or the facade, regenerate and commit them.

### iOS

There is no `.xcworkspace`; generate the project first. The Rust core is consumed as a local SwiftPM package
(`../bindings/swift`, product `Chencang`).

```sh
cargo run -p xtask -- build-ios      # XCFramework first (required)
cd ios && xcodegen generate
xcodebuild -project ios/ChencangiOS.xcodeproj -scheme ChencangCompanion \
  -destination 'generic/platform=iOS Simulator' -configuration Debug CODE_SIGNING_ALLOWED=NO build
cd ios/ChencangShared && swift test --parallel   # unit tests run on macOS via SwiftPM
```

The `ChencangCompanion` app embeds the `ChencangAction` Action Extension; shared logic lives in the `ChencangShared` package.

### Android

`~/.m2` must contain the core AAR before any Gradle build resolves it (consumed via `mavenLocal()`, version pinned in
`android/gradle/libs.versions.toml`).

```sh
cd android
./scripts/publish-aar-local.sh       # runs xtask build-android (needs ANDROID_NDK_HOME) and publishes the AAR to Maven Local
./gradlew assembleDirectDebug assemblePlayDebug   # flavors: direct (self-update) / play
./gradlew :shared:testDebugUnitTest :app:testDirectDebugUnitTest :app:testPlayDebugUnitTest
```

`:shared` JVM tests load the host-built native library via `jna.library.path` and `uniffi.component.chencang.libraryOverride`.
Instrumented tests need an API 35 emulator. Release signing reads an untracked `android/keystore.properties` and falls back
to debug signing if it is absent.

### Design tokens

```sh
cd design && npm run tokens   # regenerates Moyu.swift / Moyu.kt / moyu_colors.xml
```

Commit the regenerated files together with the token change; the `design-tokens` CI job fails on drift.

### Public-repo scan

```sh
scripts/public-scan.sh        # also runs in CI together with gitleaks
```

## Contributing

Issues are welcome. Pull requests are reviewed and merged by the maintainers. Key engineering rules:

- **Zero network for text.** Do not add a server, an outbound request or a cloud dependency to the text path.
- **No hardcoded UI values.** Colours, sizes, fonts and durations come from `design/tokens/*.json`; edit the tokens and regenerate.
- **`core/` is security-critical.** Changes (especially `primitives/`, `handshake/`, `session/`, `wire/`) need KAT verification
  and review by cryptographically literate reviewers.
- **Keep generated bindings in sync.** Regenerate and commit the Swift / Kotlin bindings after any `chencang.udl` or facade change.
- **Keep `RUST_MIN_STACK`** in `.cargo/config.toml`.
- **Run `scripts/public-scan.sh`** before pushing. Never commit secrets, signing keys, keystores, internal hostnames,
  account IDs or personal information.
